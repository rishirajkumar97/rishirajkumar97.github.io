Newest · Personal research 01

Cortical review harness

A verdict-only reviewer isn’t enough — an LLM will happily report a finding it can’t justify. So I made findings earn their way up a cortex.

Each review smell first enters the thalamus, which projects only to L4 and L6 — matching the published Potjans–Diesmann 2014 connection probabilities. A finding is only reported if it propagates through L4 → L2/3 → L5 and produces an actual L5 spike. Findings that can’t survive the circuit stay silent.

Review smells Thalamus L4 → L2/3 L5 spike

Recurrence closes the loop: corrections and approvals decay over 21 and 14 days into a per-smell gain, so the reviewer gradually re-weights toward the things it has historically missed. Author bias is tracked separately, so the model doesn’t simply learn to distrust a person.

Memory infrastructure 02

Episodic memory that relearns

Session context is usually thrown away. I built a memory server that turns it into durable, revisable knowledge.

A GraphRAG store over entities and multi-hop edges, plus a belief system with confidence scores that can be reinforced, superseded, and detected as stale. An observe → learn → reflect loop consolidates recent episodes into long-term beliefs, with a separate personality profile that is version-controlled and edited deliberately rather than drifting.

Deliberately SQLite-first and dependency-light: local, inspectable with standard SQL, and no vector database required to get continuity.

  • MCP server
  • GraphRAG
  • Belief revision
  • Python
  • SQLite
Agent orchestration 03

Reviewer + implementer agents

One agent reviewing its own code is a weak signal. Separating the roles is what makes it trustworthy.

A review pass and an implementation pass work from different context and different incentives: the reviewer is read-only, hunts for defects against an explicit rubric, and must evidence each finding against code or runtime behaviour. The implementer works in an isolated git worktree so the local branch and containers stay untouched.

Findings come back as severity-ranked, actionable items with a clear verdict — not a wall of suggestions. Confirmed learnings feed back into memory so the same defect class doesn’t get re-discovered next month.

  • Multi-agent review
  • Isolated worktrees
  • Rubric-driven
  • Human-in-the-loop
Durable automation 04

Issue-to-PR agent pipeline

An agent that forgets mid-task isn’t an engineer. I run coding agents on durable, resumable infrastructure.

A self-hosted Trigger.dev pipeline takes an issue through recall, diagnosis, an isolated worktree, code generation, automated verification, and a draft PR — with confidence gating and human-in-the-loop waitpoints before anything ships.

Supports both Claude Code and a Cursor-based local adapter, records attempt traces for offline evaluation, and treats the model as one replaceable component rather than the system itself.

  • Trigger.dev
  • TypeScript
  • Durable workflows
  • Evals
  • Confidence gating

How I think about AI systems

  • Verification over generation. A model’s output is a hypothesis until something independent checks it.
  • Memory beats context windows. Continuity comes from structure and revision, not from stuffing more tokens in.
  • Constraints are the product. Rubrics, gates, and worktree isolation are what make agent output usable.
  • Evaluation is not optional. If you can’t measure the harness, you’re just hoping the model behaves.
